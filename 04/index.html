04 / 課題の確認

前回の振り返り

前回のワークシートを読み、次の3つを自分の言葉で確かめます。長い説明は不要です。まずは一つずつ、1行で書きましょう。

困っている人

例：問い合わせに返事を書く受付担当。

困っている場面

例：希望日や人数の書き忘れを、毎回探している。

楽にしたい作業

例：足りない項目を確認しやすくしたい。

「仕事を全部自動にしたい」だと、最初の作業が決まりません。「返事を書く前に、必要な情報があるか確かめたい」まで絞ると、何を作るか考えやすくなります。

未完成からの再開

前回のスライドがなくても参加できます。「最近、同じ確認を何度もしたこと」を一つ思い出してください。持ち物の確認、行事の準備、問い合わせへの返事などで構いません。思いつかない場合は、配布した問い合わせの例をそのまま使います。

05 / 制作範囲

最初の機能

「機能」とは、道具がしてくれる一つの働きです。たとえば「入力漏れの確認」「合計の計算」「持ち物の一覧表示」です。最初は一つだけ選びます。

完成品ではなく、「このやり方で少し楽になりそうか」を試す見本を作ります。これが試作品（プロトタイプ）です。AIにプログラムを書いてもらっても、できた道具が生成AIにつながるわけではありません。今回は決めたルールで動かし、固定の結果を使う場合は「見本」と明記します。

自分の課題の例今回試せる小さな機能今回は対象外
持ち物を忘れやすい自分で選んだ行き先に応じて、決めておいた持ち物を表示。予定や天気の自動取得。
案内文の項目が抜ける日時・場所・持ち物の入力漏れを確認。文章の意味の自動判断やSNS投稿。
費用の足し算が面倒人が入れた金額の合計を表示。会計処理、税額の判断、請求書送信。
問い合わせの情報が足りない人が入れた希望日と人数を確認。メールの読み取り、送信、予約確定。

文章の自動要約が中心の方は、最初は「文章を入れる欄」と「見本の要約を表示する欄」だけでも構いません。要約そのものの品質は、AI未接続の画面見本では確かめられないことをメモに残します。

完成の目印

「いい感じに動く」ではなく、入力と結果をセットで決めます。問い合わせの例なら、「希望日だけ入れて人数を空にすると、『人数が未入力』と出る」です。自分の題材でも、この形で一つ書いてください。

機能の絞り込み
私の課題は「［自分の課題］」です。
今回試したい作業は「［一つの作業］」です。
ブラウザーだけで試せる、小さな機能に絞りたいです。
外部通信、生成AIへの接続、ログイン、データ保存、実送信は使いません。
入力するもの・押すボタン・表示する結果・今回は作らないものを提案してください。
自由な文章理解が必要なら、決めたルールか「見本」と明示した固定表示で代わりに試せる範囲を説明してください。
候補は多くても二つにし、どちらにするか私の返事を待ってください。
まだプログラムは作りません。
06 / 画面設計

画面の下書き

紙に四角を三つ描きます。「入力」「ボタン」「結果」と書いてください。絵の上手さは関係ありません。どこに何があると、自分が使いやすいかを考えます。

  1. 入力欄の名前

    「データ」より「希望日」「人数」のように具体的に書きます。自由な文章を一つ入れる欄にするより、日付と人数を分ける方が、最初の試作品では確認しやすくなります。

  2. ボタンの名前

    「実行」より「確認する」「合計する」のように、押した後の動きが分かる名前にします。ボタン名は画面の操作を伝えるため、動詞で構いません。

  3. 結果の内容

    成功したときだけでなく、入力が足りないときの文章も決めます。「エラー」だけではなく、「人数を入力してください」と、次の行動が分かる文章にします。

自分の作業：作業メモ【1】の入力・ボタン・結果を埋めます。紙に描いた場合は、AIに渡すために短い文章へ書き直します。写真を添付するなら、机の上の資料や周囲の人が写っていないか確認します。

ここで、一度声に出して説明。
「私はここに○○を入れます。このボタンを押すと、ここに○○が出ます。」と言えれば、制作の依頼に進めます。

参考例用の依頼文

08 / 保存と表示

ファイルの保存

AIの会話画面にプログラムが出ただけでは、パソコンのファイルになっていないことがあります。実際に保存先を開き、ファイルがあることを確認します。

ダウンロードでの保存

  1. ダウンロード

    AIの画面にファイルがある場合は、ダウンロードします。表示やボタン名は使うAIによって違います。会話画面の中だけのプレビューは、パソコンへの保存とは別です。

  2. 保存先と名前の確認

    ファイルを ai-terakoya-04 フォルダーへ置きます。名前を 04_my_tool_v1.html にします。すでに同じ名前があれば、上書きせず、今あるファイルを先に確認してください。

  3. ブラウザーでの表示

    ファイルを右クリックし、「プログラムから開く」「このアプリケーションで開く」などから普段のブラウザーを選びます。ダブルクリックでブラウザーが開くなら、それでも構いません。

コードからの保存

HTMLは、画面を作るための文字です。<!doctype html> から始まり、最後が </html> になるような長い文章が表示されます。途中を省略せず、最初から最後まで保存します。

Windowsのメモ帳

  1. メモ帳の新しい文書を開き、AIのHTML全文を貼り付けます。
  2. 「名前を付けて保存」で作業用フォルダーを選びます。
  3. ファイルの種類を「すべてのファイル」、文字コードを「UTF-8」にし、名前を 04_my_tool_v1.html にします。
  4. 保存後、末尾が .html.txt でないか確認します。

Macのテキストエディット

  1. 新しい文書を開き、「フォーマット」から「標準テキストにする」を選びます。
  2. AIのHTML全文を貼り付けます。
  3. 作業用フォルダーへ 04_my_tool_v1.html の名前で保存します。
  4. 拡張子の確認が出たら .html を使います。文字コードを選ぶ画面ではUTF-8にします。

「拡張子」は、ファイル名の最後の .html や .txt の部分です。見えていない場合は、ファイルの情報・プロパティなどで名前を確認します。Wordなどの文書作成ソフトでは保存せず、文字だけを扱うメモ帳などを使ってください。

コード欄の外にある説明文や、コードを囲む3つの記号 ``` は入れません。「ここに続き」「省略」と書かれている場合は、次の依頼を送ります。

全文の再出力
保存してブラウザーで開きたいので、HTMLを省略せず全文で出してください。
最初の <!doctype html> から最後の </html> までを、一つのコード欄にまとめてください。
説明文はコード欄の外に置き、複数のファイルに分けないでください。
依頼した機能や条件は変更しないでください。

Macの保存手順の参考：Apple「MacのテキストエディットでHTML書類を扱う」。画面名はOSのバージョンで異なる場合があります。

09 / 1回目の確認

最初の動作確認

最初は、うまく進むはずの入力を一つ試します。下は配布した問い合わせ見本の場合です。自分の試作品なら、同じ手順で入力例を置き換えてください。

  1. 使うファイルの確認

    自分で作った 04_my_tool_v1.html を開きます。制作が止まった方は、動作見本を別のタブで開きます。見本の結果は、自分の試作品の確認結果とは分けて記録してください。

  2. 期待する結果の記入

    作業メモ【2】のAへ、入力例と、出てほしい結果を先に書きます。問い合わせ見本なら「2026年10月12日、4人 → 入力項目の確認完了」です。

  3. 入力と実行

    希望日の欄で2026年10月12日を選び、人数に 4 を入れます。相談メモは空でも構いません。「確認する」を1回押します。

  4. 結果の読み取り

    結果の見出しだけでなく、日付・人数・注意書きも読みます。入力した内容が違っていないか、「予約確定」など作る予定のない表示が出ていないか確認します。

  5. 実際の結果の記録

    作業メモの「実際の結果」に画面の言葉を書きます。期待どおりなら「一致」、違えば「不一致」、まだ操作できていなければ「未確認」とします。

参考例の正しい読み方。
「入力項目の確認完了」は、日付と人数がそろったという意味です。空き状況や料金は確認していません。予約できる、送信された、という意味ではありません。

画面の部品と動き

ボタンが見えていても、押した後の動きが作られていない場合があります。画面の見た目を作るHTMLやCSSに加えて、動きを担当するJavaScriptが必要です。これらの言葉を暗記する必要はありません。「見えている」と「動く」を、自分の操作で分けて確かめることが大切です。

B｜不足2026年10月12日空欄人数が未入力。入力するよう案内。
C｜範囲外2026年10月12日13人数上限を超過。担当者へ要確認。
D｜全部空空欄空欄希望日と人数の両方が未入力。

見本の人数上限は12人です。この数字は練習のための架空の条件で、実際の施設のルールではありません。12人なら通常の確認、13人なら担当者への確認、という違いも確かめます。

自分の試作品の確認表

持ち物の道具なら「行き先を選んだ場合」と「選んでいない場合」。合計の道具なら「金額あり」「一つ空欄」「想定していない値」「全部空欄」です。空欄を0円とするのか、入力を求めるのかは、先に自分で決めてから試します。道具の出した結果に合わせて、正解を後から変えないようにします。

変更後の表示

  1. 一度結果を表示します。
  2. 入力を一つ変えます。問い合わせ見本なら、4人を13人へ変えます。
  3. 古い結果が消えるか、再確認の案内になるかを見ます。
  4. もう一度ボタンを押し、新しい入力に合う結果へ変わることを確かめます。

入力だけ13人に変わり、結果に「4人・確認完了」が残ると、見間違いにつながります。今回の依頼文では、入力を変えたら古い結果を消すよう指定しています。

追加確認｜0人・小数・境目

問い合わせ見本では、0人・マイナス・2.5人は入力の誤りです。1以上の整数を入れる案内が出ることを確認します。12人と13人も続けて試してください。見た目が数字でも、道具が想定する数字とは限りません。

11 / 改善

不具合の修正

「思ったとおりにならない部分」を、ここでは不具合と呼びます。見つかったら、自分が失敗したのではなく、直す場所が分かったと考えましょう。一度にたくさん直すと、何が原因だったか分かりにくくなります。

修正依頼の4点

「動きません」だけでは、どこを直せばよいか伝わりません。使っているHTMLファイルと、上の4点を一緒に渡します。ファイルを添付できない場合は、現在のHTML全文を貼り付けます。

一つの不具合の修正
添付した 04_my_tool_v1.html の、次の不具合だけを直してください。
入力したもの：［実際の入力］
操作の順番：［何をして、何を押したか］
期待した結果：［出てほしいもの］
実際の結果：［画面に出た文字や、変化がなかった状況］

原因と直す場所を、初心者に分かる言葉で短く説明してください。
関係のない機能や見た目は変えず、元のファイルも上書きしないでください。
修正版は 04_my_tool_v2.html という別ファイルにしてください。
外部通信・AI接続・データ保存を追加しないでください。
保存できない場合は、修正後のHTML全文を省略せず出してください。
今回の不具合の再確認と、ほかに確かめる項目を示してください。
実際に操作していないことは「未確認」と明記してください。

修正後の再確認

  1. 別名での保存

    修正版を 04_my_tool_v2.html として保存します。前の v1 を残せば、比べたり戻したりできます。次の修正では v3 と数字を増やします。

  2. 開いているファイルの確認

    v2 をブラウザーで開きます。前のタブの v1 を見たまま「直っていない」と判断しないよう、アドレス欄や開いたファイル名を確かめます。

  3. 同じ操作の繰り返し

    不具合が起きたときと、同じ入力・同じ順番で試します。別の入力では、直ったかどうかの確認になりません。

  4. ほかの入力の再確認

    A〜Dももう一度試します。一つを直した影響で、別の入力がうまく動かなくなっていないか確認します。

不具合が見つからない場合。
無理に不具合を作る必要はありません。「入力例がほしい」「結果の説明が難しい」など、使い方の案内を一つ改善します。それも、変更前のファイルを残してから行います。
12 / 使い勝手

使いやすさの確認

作った本人は使い方を知っています。初めて見る人が、説明なしで使えるかも確かめましょう。隣の人に頼める場合は、「ここへ入力するんだよ」と先に教えず、画面を見てもらいます。一人の場合は、少し間を空けてから声に出して読み直します。

見るところ具体的な確認
入力欄何を入れる欄か分かるか。入力例があるか。
ボタン押すと何が起きるか、名前から分かるか。
結果何が分かったかと、次に何をするかが読めるか。
注意書き試作品であること、できないこと、未送信であることが分かるか。
小さい画面ブラウザーの横幅を狭くしても、入力欄や文字が重ならないか。
キーボードTabキーで入力欄とボタンへ進めるか。選択中の場所が分かるか。

依頼の例：「人数の欄の下に『1人以上の整数。13人以上は担当者へ確認』という説明を加えてください。判定のルールは変えないでください。」見た目の変更でも、保存後にもう一度入力して確認します。

役立ち方の確認

速さだけでなく、「必要な項目を思い出せる」「次に何を聞けばよいか分かる」という助けもあります。もし時間を比べるなら、架空の同じ作業で、道具なし・道具ありを試します。入力、結果を読む時間、手直しの時間も含めて記録してください。1回速かっただけで、毎回その時間を減らせるとは限りません。

13 / 操作の補助

困ったときの対処

まず「何を開いて、どこまで進んだか」を確認します。分からないまま同じ操作を繰り返さず、画面の文字とファイル名を講師に見せてください。

困ったこと最初の確認次の操作
文字やコードだけの表示メモ帳で開いていないか。ファイル名が .html.txt ではないか。本当の拡張子を確認し、HTMLファイルをブラウザーで開く。
白い画面HTMLの一部だけを保存していないか。別の空ファイルを開いていないか。ファイル名を確認し、AIに全文を出してもらう。元は残して別名で保存。
ボタンに反応なし画面の下へ結果が出ていないか。動く試作品ではなく、見た目だけの下書きではないか。入力と操作の順番を記録し、今のHTMLを添えて修正依頼。
直したはずの画面が古いv1 と v2 のどちらを開いているか。作業フォルダーから新しい方を開く。保存済みなのに古ければ再読み込み。
AIの利用上限作ったファイルや作業メモが手元にあるか。今回の外部接続なしの試作品は、AIとの会話が止まっても操作可能。確認の練習を先に進める。
制作が進まない一度にたくさんの機能を頼んでいないか。入力・ボタン・結果の一つの流れに絞る。難しければ配布見本で確認を練習。
AIの回答と実際が違う回答を読んだだけで「動いた」としていないか。実際の操作結果を優先し、不一致として記録。AIに画面の事実を伝える。
