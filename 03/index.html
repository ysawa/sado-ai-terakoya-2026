02 / AIの入口を準備

無料枠で止まったときのために、Geminiも用意する

前回は、受講中にChatGPTの無料枠の上限に達した方が多くいらっしゃいました。応急措置として、Geminiでも作業を続けられるようにしておきましょう。

最初に約束：個人情報・機密情報はAIに載せません。
実名、連絡先、顧客名簿、社内の未公開資料、契約情報、パスワードやAPIキーは入力・添付しないでください。Geminiに限らず、ChatGPT・Claudeでも同じです。自分の困りごとは、特定の人や組織が分からない一般的な場面に置き換えて、新しくメモにします。名前を消しただけで特定できる内容や、言い換えても秘密に当たる内容は使いません。迷ったら配布する架空の素材を使います。有料版なら何でも渡してよい、という意味ではありません。

① Geminiアプリを入れて、使えることを確認

  1. スマートフォンでは、App Store／Google PlayでGoogle提供のGeminiを選び、インストールします。公式のアプリ案内からたどると安心です。Androidではアシスタントの設定変更が案内されることもあるため、内容を読んで選びます。
  2. Googleアカウントでログインします。パソコンでは、まずGemini Web版を開けば構いません。非公式のデスクトップアプリを探す必要はありません。
  3. 「架空のお店の問い合わせ受付を整理したいです。最初に聞くことを3つ挙げてください」と送り、返事を確認します。

アプリの提供条件は端末・地域・年齢・アカウントで異なります。利用できない場合は、使えるWeb版や今までのAIで進めてください。

② パソコンにGemini CLIを導入

CLIは、文字を入力して操作する仕組みです。Windowsは「ターミナル／PowerShell」、Macは「ターミナル」を開きます。画面の指示を一つずつ実行し、前の行が終わってから次へ進みます。

学校・会社・貸与PCへのインストールは管理者や講師に確認します。権限の警告が出ても、管理者権限や制限解除を自己判断で使わないでください。導入で止まったら、Web版ルートで同じ演習に進めます。
PCのターミナル｜Node.jsの確認
node --version
npm --version

バージョンが出なければ、Node.js公式サイトのLTS版を導入し、ターミナルを開き直します。Gemini CLIの公式要件はNode.js 20以上です。OSなども最新の動作要件で確認してください。

PCのターミナル｜インストール → 確認
npm install -g @google/gemini-cli
gemini --version

Windowsで npm.ps1 の実行が制限される場合は、同じコマンドの npm を npm.cmd に替える方法があります。gemini.ps1 も同様なら gemini.cmd を使います。解消しなければWeb版へ。Macで権限エラーが出た場合も、むやみに sudo を付けません。

③ 教材用フォルダーで起動・ログイン

  1. エクスプローラー／Finderで、教材専用の sado-ai-03 フォルダーを作ります。配布素材をそこへ保存します。顧客資料や仕事のフォルダーを混ぜません。
  2. ターミナルで cd "教材フォルダーの実際のパス" と入力して移動します。この日本語部分はそのまま実行せず、自分のフォルダーの場所に置き換えます。Windowsではフォルダー内の「ターミナルで開く」も利用できます。
  3. pwd で現在の場所を確認し、gemini で起動します。フォルダーの信頼を聞かれたら、教材専用フォルダーであることを確かめます。
  4. Sign in with Google／Googleでログインを選び、ブラウザーで認証します。個人向け演習では通常、APIキーは不要です。組織アカウントでプロジェクトや権限を求められたら勝手に作成せず、管理者へ確認するかWeb版で進めます。

認証方法によって利用枠や情報の扱いが変わります。公式の認証案内・規約とプライバシーを確認してください。学習への利用を制限する設定があっても、この講座では秘密情報を渡しません。

動作確認だけは、参考①の架空メモを教材フォルダーへ保存して使います。本編では自分の困りごとへ切り替えます。

Gemini CLIの会話欄｜最初は読み取りだけ
この教材フォルダーの 030_material_work_memo.txt だけを読み、
M01に書かれている担当者の役割を教えてください。
他のフォルダーは読まず、ファイルの作成・変更・削除はまだ行わないでください。

返事を自分で開いたM01と比べます。読み取りや実行の許可画面では対象を確認し、不要な操作は許可しません。CLIの終了は /quit です。公式のコマンド一覧も参照できます。貸与・共用PCでは最後にログアウトし、講師の案内に沿って認証情報を残さないようにします。CLIを終了することと、ログアウトすることは別です。

03 / 利用枠との付き合い方

おすすめは有料版。けれど、使い放題ではない

継続して使うなら、ChatGPTまたはClaudeの有料版への入会をおすすめします。まずは使いやすい方を一つ選び、ChatGPT Plus／Claude Proなどの内容を確認しましょう。両方の契約や、この場での契約は必須ではありません。

普段は軽いモデル

書き換え、箇条書き、決まった形式への整理は、利用できる廉価・軽量モデルから試す。

難しい箇所だけ高性能に

矛盾の検討、複雑な設計、解けない問題だけ切り替える。短い指示で対象を絞る。

使用量をこまめに確認

開始前・演習の区切り・大きな処理の前に、画面で確認します。ワークシートへの記入は不要です。

「廉価」は、料金体系で意味が違います。 月額プラン内では軽いモデルを使っても月額がその都度安くなるわけではなく、利用枠を長持ちさせやすくなります。APIや追加クレジットでは、別料金が発生する場合があります。定額契約とAPIの従量課金は別物です。講座のために自動課金を有効にする必要はありません。
使うサービス確認する場所気をつけること
ChatGPT／CodexChatGPTは画面の制限通知・再開案内。Codexは使用量画面、CLIは /status。ChatGPTの通常チャットとCodexの表示を混同しない。利用枠・モデルの提供範囲はプランと機能で異なる。
Claude設定（Settings）→ 使用量（Usage）。モデルや利用枠の内訳、次のリセット時刻を確認。ClaudeとClaude Codeで利用枠を共有する場合がある。有料でも上限がある。
Gemini CLI会話欄で /stats model。モデルの設定は /model、操作に迷ったら /help。セッション内の使用トークンと契約の残量は別の値。表示項目は認証方法で異なる。Geminiにも上限がある。

モデルは、選択画面にある軽量・低コストの選択肢を確認します。例として、GeminiのFlash系、ClaudeのHaiku系、Codexのmini系などがありますが、契約・アプリによって選べないものもあります。「Fast」と書かれた高速モードが低コストとは限りません。

AIを替えるときの引き継ぎ｜空欄を自分で埋める
目的：［自分が選んだ困りごと］を整理し、解決方針を発表する。
決定：［ここまでに自分で決めたこと］。実データや外部送信は扱わない。
次の作業：［演習番号と、次に確かめたいこと］。
添付した／このフォルダーの 03_workbook.txt の記入済み部分を使ってください。
事実と推測を分け、質問は一度に一つだけ。私の回答を待って進めてください。

公式情報：OpenAIのプラン・利用量／Claude Pro／Claudeの利用制限／Gemini CLIの利用枠。2026年9月6日確認。価格・モデル名・枠の数値は変わるため、契約時の画面で確認します。

04 / 今日作るもの

作る前に、「何を楽にしたいか」をはっきりさせる

第2回はファイルを加工しました。今回は、その前後の仕事も見て「どの作業を変えると役に立つか」を考えます。いきなり大きなシステムを作る必要はありません。

① 自分で選ぶ課題

誰がどんな場面で困り、どうなったらうれしいか。

② 自分で選ぶ方針

現状の流れを見て、最初に試す案と人が確認する場所を決める。

③ 発表スライド

課題と解決方針が伝わるようにまとめる。枚数は内容に合わせて決める。

対話と自分の決定を 03_workbook.txt に保存し、最後に 03_my_proposal.html というスライドにします。図を描けたら 03_workflow.html に保存してスライドへ活かします。次回の詳しい試作指示書は、方針が固まってから追加できます。

今日の到達点：「私はこれに困っていて、まずこの方法を試したい」と、自分の言葉で説明できること。すべてが決まっていなくても、分からないことと次に確かめることを残せれば十分です。

どの演習も「自分で考える → AIと対話 → 自分で決める」

最初に短く自分の考えを書きます。AIには一問ずつ聞いてもらい、自分が答えます。最後に、採用する内容を自分で選び、ワークシートに残します。AIの回答をそのまま提出するのではなく、少なくとも一か所を自分の言葉で言い直しましょう。

2〜3往復したら「いったんここまでをまとめて」と頼み、先へ進むか、もう少し考えるかを自分で決めます。AIが質問を並べたら「一問ずつに戻して」と伝えます。まだ答えられないことがあっても、未確認として次へ進めます。

演習は同じ会話で続けられます。会話やAIを替える場合は、保存したワークシートを添付・指定します。各プロンプトの「私のメモ」は、このワークシートを指します。

05 / 自分の素材を用意する

自分の困りごとを、今日の素材にする

仕事だけでなく、暮らしや地域活動の困りごとでも構いません。「毎回探してしまう」「同じことを何度も書く」「予定を忘れる」「決めるまでに疲れる」など、最近の場面を思い出します。大きな社会問題や立派なテーマでなくて大丈夫です。

  1. 下の記入用ワークシートを保存し、03_workbook.txt という別名でコピーを作ります。
  2. 冒頭の「私の素材メモ」に、最近困った場面を3行ほど書きます。完成した文章にする必要はありません。
  3. 個人や組織が特定できる情報、秘密情報がないか自分で確認してからAIへ渡します。
思いつかなければ：「日々の献立を決める」「届いた案内から締切を拾う」「地域行事の持ち物を準備する」などから、自分が気になる場面を選びます。それでも迷う場合は、下の架空の受付例で練習して構いません。題材は途中で選び直せます。

06 / 演習1

「なんとなく大変」を、困りごとの一文にする

「忙しい」「AIで自動化したい」だけでは、何を変えるべきか決まりません。誰が・どんな場面で・何に困り・どんな影響があるかの4つに分けます。

演習1｜困りごとを3つ出して、1つ選ぶ
  1. まず自分で、仕事・暮らし・地域活動の困りごとを3つ書きます。1つしか思いつかなければ、その場面から始めて構いません。
  2. AIに一問ずつ聞いてもらい、「最近、実際に困った場面」を話します。個人や組織を特定する情報は出しません。
  3. 候補を比べ、自分が解決したいものを一つ選びます。「これを選んだ理由」「どうなったらうれしいか」も自分の言葉で書きます。
自分の困りごとを、一問ずつ掘り下げる
あなたは私の困りごとを整理する聞き手です。03_workbook.txt の私の素材メモを使います。
質問は一度に一つだけにし、必ず私の回答を待ってください。
最初は「最近、面倒だったり困ったりしたのは、どんな場面ですか？」と聞いてください。
私の回答に合わせ、誰が・いつ困るか・今の対応・影響・どうなりたいかを一つずつ聞いてください。
答えていないことや体験を創作せず、まだ解決策やアプリの提案はしないでください。
題材が思いつかない場合だけ、身近な場面を2つ例示し、私が選ぶのを待ってください。
十分に話せたら、私の言葉から候補を整理し、取り組む一つを私に選ばせてください。
最後に、私が選んだ課題の一文を示し、私の言い直し・確認を待ってください。
もう一歩：「担当者が注意すればよい」で終わらない別の言い方を考えます。人の能力を責めず、情報や手順の問題として書き換えましょう。
07 / 演習2

AIに渡す前に、事実・古い情報・要確認を分ける

メモは必ずしも正しいとは限りません。AIが上手にまとめるほど、古い情報まで正しく見えることがあります。元の記述へ戻れる根拠番号を付けます。

分類この素材の例扱い方
現在の事実直近5営業日で60件（M11）期間を付けて使う。年間平均と呼ばない。
古い情報上限15名（M09）最新版R01の12名を採用。食い違いを記録する。
要確認料金・送迎可否（M10・R03）確定資料がないため断定しない。
推測AI導入で作業が半分になる素材にない。予測なら仮定として検証する。

自分のメモにも「本当にそう？」と印を付ける

まず自分で、実際に経験したことに○、推測に△、まだ分からないことに？を付けます。「いつも」「みんな」「すごく時間がかかる」などの言葉を一つ選び、どこまで言えるか確かめましょう。数字の記録がなければ未測定で構いません。

自分の言葉の根拠を確かめる
私の素材メモと、選んだ困りごとの一文を読み、根拠が曖昧な表現を一つだけ選んでください。
「実際に確かめたことですか、記憶や推測ですか？」など、質問を一つして私の回答を待ってください。
その後も一問ずつ確認し、私が分からないと答えたことは未確認として残してください。
経験したこと、推測、要確認、使わない情報を分け、元の私の言葉やメモ番号を付けます。
制度・料金・社内ルールなどを勝手に補わず、外部検索で埋めないでください。
最後に分類案を示し、採用する内容と保留する内容を私に確認してください。
参考例の確認の観点｜受付メモを使う場合

人数上限はR01の12名。ただし「12名以内なら予約確定」ではありません。料金・空き状況・送迎の確定資料はありません。M13の「2日」は1件の経験で、全件の平均ではありません。予算・導入判断者・現在の保存期間も未確認です。

もう一歩：AIに「あなたが素材にないことを断定した箇所だけを列挙して」と頼みます。その回答も自分で確認してください。
08 / 演習3

現状の流れを、担当・入力・出力で描く

業務フローは、仕事が誰から誰へ、どの順序で渡るかを示す地図です。暮らしの困りごとなら「いつ始めて、何ができれば終わりか」を描けば構いません。受付の参考例では、開始を「問い合わせが来る」、終了を「Aが返信し、一覧を更新する」と決め、予約確定まで広げません。

まず、自分の今のやり方を3〜5手順で書く

「受け取る → 探す → 書く → 確かめる」など、動詞で並べます。困る場所に★を一つ付けてからAIへ渡しましょう。担当が自分一人でも構いません。

自分が書いた手順を、一問ずつ確かめる
私が書いた現在の手順を使って、流れを整理します。

本編が進んだ方は、自分に必要な課題を選んでください。講座中に先へ進むために使っても、後日取り組んでも構いません。終了時には発表とアンケートに戻ります。

A｜AIなしでも試す

自分の課題に使える入力用紙や確認チェックリストを作ります。自分で考えたケースを人だけで処理し、AIを使う案と手間・確認負担を比較してください。

B｜担当者が交代したら

翌日、別の人が引き継ぐ場面を想定。状態・次の作業・保留理由だけで再開できる引き継ぎ票を作ります。代行権限など未決定の条件は明記します。

C｜例外を10件追加

日付変更、複数の希望日、曖昧な人数、古いルール、空の入力など。期待する結果を先に書き、フローを通してから比較します。

D｜期待した効果が出ないとしたら

自分の案の手直しや確認が増える場合を考えます。数字がなければ記録方法を決めます。計算を練習するなら、参考例の確認時間4分・7分・10分・12分で比べられます。

E｜別のAIへ引き継ぐ

架空の素材と3行の引き継ぎメモを使い、利用可能な別AIで同じ作業を依頼。失われた条件・増えた推測を比較し、メモを改善します。無理に有料契約しません。

F｜もう一つの困りごと

最初に挙げた別の候補でも、課題の一文・現状・解決方針を考えます。最初のテーマと比べ、どちらを先に試したいか、自分の選択を見直します。

G｜比較ポスターを作る

現状と改善後、期待する効果、まだ分からないことを1枚のHTMLにまとめます。色だけに頼らず、スマホ表示と文章の根拠も確認します。

H｜試作品の紙芝居

入力前・整理結果・情報不足・担当者確認待ちの4画面をHTMLの静的な見本にします。生成AIに未接続の見本と明示し、実データやキーは入れません。
