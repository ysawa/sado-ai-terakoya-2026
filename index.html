05 / Choosing AI tools

同じAIでも、「相談」と「仕事」と「開発」は違う

名前が似ていても、AIへ任せる範囲と、結果の受け取り方が違います。境界が重なる機能もありますが、最初は次の3段階で考えると迷いません。

STEP 1｜相談する

Chat

ChatGPT / Claude

質問、説明、アイデア出し、短い文章の下書き。主な成果は会話の中の回答です。

STEP 2｜仕事を任せる

Work / Cowork

ChatGPT Work / Claude Cowork

調査、資料整理、文書・スライド・表の作成など、複数工程の仕事を確認できる成果物まで進めます。

STEP 3｜開発する

Coding agent

Codex / Claude Code

開発フォルダを読み、ファイルを編集し、コマンドやテストを実行して、動くコードと変更差分を作ります。

✓
この講座で使いたいのは Codex または Claude Code

HTMLファイルを実際に作り、ブラウザで確認し、直すところまで体験するためです。通常のChatへコードを質問するだけではなく、講座用フォルダを開発エージェントに渡して作業します。

比較図｜同じ依頼でも、返ってくるものが違う

Chat「こんなHTMLです」という回答
Work / Cowork調査や資料をまとめた成果物
Codex / Claude Codeフォルダ内のHTMLを作成・修正・確認

機能には重なりがあります。ここでは「何を中心に作業する画面か」で整理しています。

Geminiは使ってもよいですか？

この講座程度の、公開してよい内容の質問やアイデア出しには使って構いません。ただし、ハンズオンの説明はCodex / Claude Codeを基準にします。講座の実務方針として、個人向けGeminiを現実の仕事へ使うことは非推奨です。

個人向け Gemini Apps

Keep Activityがオンの場合、会話や共有したファイルなどがサービス改善・生成AIの学習に使われ、人が確認する場合があります。実務の秘密情報は入力しません。

組織契約 Google Workspace版Gemini

対象エディションでは、組織外のモデル学習へ許可なく使わない保護が適用され、管理者が利用やデータアクセスを制御します。

クラウド契約 Google Cloud / Vertex AI

顧客の許可・指示なしに、顧客データをAI/MLモデルの学習や微調整へ使わない契約上の制限があります。保持期間は別に確認します。

「学習に使わない」と「保存しない」は別です。個人版GeminiはKeep Activityをオフにできます。その場合、今後の会話は原則モデル学習に使われませんが、サービス提供などのため最大72時間保存され、一部の連携機能が使えなくなります。Vertex AIも学習制限はありますが、完全なゼロ保持には追加設定や条件の確認が必要です。
実務データは「一律禁止」ではなく、条件を整えて判断します。顧客情報や契約情報がなければ進められない仕事もあります。まず、入力内容をモデルの学習に使わない企業向け契約・設定であることを確認します。その上で、会社・顧客とのルール、利用目的、入力する必要性を確認し、必要最小限に絞る・匿名化するなどの対策をしてから判断します。
認証情報は別です。パスワード、APIキー、秘密鍵、認証コードなどは、学習に使われない設定でも原則としてAIへ入力しません。漏えいすると第三者にサービスやシステムを操作される危険があります。誤って入力した場合は、すぐに管理者へ連絡し、無効化・変更・再発行します。
06 / What is AI?

AIは、ひとつの製品名ではない

AI（人工知能）は、人が「知的」と感じる認識・予測・生成・判断支援などを、コンピュータで実現する技術の総称です。

図3｜AIの中に、機械学習・深層学習・生成AIがある

AI（人工知能）ルールベースなども含む広い概念
機械学習データから規則を学ぶ
深層学習多層ニューラルネットワーク
生成AI文章・画像・音声・コードを作る
種類何をするか身近な例注意点
ルールベース人が決めた条件で処理する「気温が30度以上なら警告」想定外の条件には弱い
機械学習過去データから傾向を学ぶ需要予測、迷惑メール判定学習データの偏りを受ける
識別AI入力を分類・検出する画像内の物体検出、異常検知「なぜ」の説明が難しい場合がある
生成AI条件に合う新しい内容を作る文章、画像、音声、動画、コードもっともらしい誤りも生成する

生成AIは「コピー機」ではなく「パターン生成器」

生成AIは、大量のデータから言葉や画像のパターンを学び、入力された指示に合いそうな出力を組み立てます。学習した文章をそのまま検索して取り出す仕組みとは異なります。一方で、学習データに含まれる偏りや誤りの影響は受けます。

08 / Generative AI & LLM

LLMは「次に続きそうなもの」を予測する

LLM（Large Language Model、大規模言語モデル）は、文章を小さな単位に分け、文脈に続く可能性の高い単位を予測しながら文章を作ります。

1. 文章をトークンに分ける

AIは文章をそのまま人間と同じように読むのではなく、トークンという処理単位へ分けます。トークンは単語と一致することもあれば、単語の一部や記号になることもあります。

図7｜トークン化のイメージ（実際の分け方はモデルごとに異なる）

佐渡の魅力を紹介する。

2. 次の候補に確率をつける

たとえば「佐渡の海は」の続きを作るとき、モデルは文脈から複数の候補に確率をつけ、その中から次のトークンを選びます。選ばれた語を加え、同じ処理を繰り返します。

「答えを知っている」と「自然な続きを作れる」は違う

LLMの中心は次トークン予測です。そのため文章が自然でも、内容が正しいとは限りません。存在しない制度、数字、URL、人物の発言などを、自然な文体で作ることがあります。これが一般にハルシネーションと呼ばれる現象です。

上手な使い方：AIの最初の出力を「完成品」ではなく「確認すべき案」として扱います。根拠が必要な事実は、公式資料や原文へ戻って確かめます。
09 / Transformer

Transformerは、文脈の関係をまとめて見る

Transformerは2017年の論文「Attention Is All You Need」で提案されたニューラルネットワークの構成です。現在の多くのLLMを支える基礎になっています。

それ以前の難しさ：順番に読むと時間がかかる

🚶RNN / LSTMのイメージ

前から順番に情報を受け渡す。時系列に強い一方、処理の並列化や遠く離れた関係の保持が難しい。

👀Transformerのイメージ

文章内の各位置が他の位置との関係を見る。計算を並列化しやすく、離れた語の関係も扱いやすい。

⚠️正確な理解のために

「全文を一瞬で人間のように理解する」という意味ではない。数値化された関連度を計算している。

Attention（注意機構）とは

Attentionは、今処理している語に対して「文章のどこを、どの程度参照するか」を計算する仕組みです。人の注意そのものではなく、語と語の関連の強さを数値で表す計算だと考えてください。

図9｜「それ」が何を指すか、周囲との関係を見るイメージ

佐渡でトキを見た。空をそれがゆっくり飛んでいた。
トキを強く参照それが
説明用の単純化した図です。「それ」と「トキ」の関係を強く参照する、といった計算を多数同時に行います。

図10｜文章が次のトークン候補になるまで（簡略図）

↓

覚える要点は2つ：①文脈内の関係をAttentionで計算する。②逐次処理だけに頼らないため、大規模な並列計算と相性がよい。
10 / GPU

GPUは、同じ種類の計算を大量に並べるのが得意

GPU（Graphics Processing Unit）は、もともと画像を高速に描画するために発展した処理装置です。多数の小さな計算を同時に進めやすく、深層学習で多用される行列計算と相性がよいため、AIの学習・利用を支えています。

図11｜CPUとGPUは「得意な仕事」が違う

CPU｜少数の高性能な担当者

複雑な判断、OSやアプリの制御、順序が重要な処理が得意。

役割分担

GPU｜多数で一斉に働く担当者

同じ種類の計算を大量に並列実行し、高い処理量を出すのが得意。

料理にたとえると

CPUは、注文を確認し、火加減を変え、急な変更にも対応できる経験豊富な料理人です。GPUは、同じ形の食材を大量に切る担当者が何百人も並ぶ調理場に似ています。どちらが優れているかではなく、仕事を分けることで速くなるのです。

「学習」と「利用」は別の場面

図12｜モデルを作る学習と、作ったモデルを使う推論

学習（Training）

  • 大量のデータからパターンを学ぶ
  • モデル内部の多数の値を調整する
  • 一般に大きな計算資源と時間が必要
→

推論（Inference）

  • 学習済みモデルへ入力する
  • 回答や画像などを生成する
  • 私たちがチャットで使うのはこちら
受講者が高価なGPUを買う必要はありません。通常の生成AIサービスでは、提供事業者側の計算基盤をインターネット経由で利用します。手元のPCは入力・表示・ファイル編集を担います。
11 / Strengths, limits & safety

AIの出力に、最後の責任は持たせられない

AIは短時間で案を増やし、試作を助けます。しかし、目的を決め、材料を選び、結果を確かめ、公開や実行を決めるのは人です。

図13｜人が主導する改善ループ

目的を決める人
材料を選ぶ人
案を作るAI
検証する人＋道具
採用を決める人

うまくいかなければ、目的・材料・指示を見直してもう一周します。

AIが得意AIが苦手・要確認人が担う
たたき台を速く作る最新情報や地域固有情報の正確性一次情報・公式情報との照合
複数案を出す曖昧な目的から唯一の正解を決める目的・優先順位・採用基準を決める
文章の要約・変換入力にない背景や暗黙の事情を知る必要な前提を与え、抜けを見つける
コードや表の試作すべての条件で安全に動く保証テストし、バックアップし、実行を判断する

入力前の信号チェック

図14｜講座で扱うデータの目安

青信号｜使ってよい

  • 自分で作った架空データ
  • 公開済みの情報
  • 個人を特定できない練習文

黄信号｜条件を整えて判断

  • 顧客情報・契約情報・未公開資料
  • 個人情報を含む業務データ
  • 会社のソースコード

学習不使用の企業向け契約・設定、社内外のルール、必要性を確認し、最小化・匿名化して扱います。

赤信号｜原則入力しない

  • パスワード、APIキー、秘密鍵
  • 認証コード、セッショントークン
  • 契約・法令・社内規程で入力が禁止された情報
「学習利用をオフ」にしても、何を入力しても安全になるわけではありません。講座では、見られて困る情報をAIへ渡さず、講座専用フォルダと架空データを使います。AIがファイル変更やコマンド実行を提案したら、対象と内容を確認してから承認します。

安全に使う5秒チェック

  • 個人情報や秘密情報が入っていない
  • 元ファイルのコピーやバックアップがある
  • AIに任せる範囲が分かっている
  • 出力の事実・数字・動作を確認できる
  • 公開・送信・実行は人が判断する
  • 迷ったら入力せず、講師へ相談する

3問で振り返る

  1. 生成AIの文章が自然でも、事実確認が必要なのはなぜですか。
    回答例

    LLMは文脈に続きそうなトークンを予測して文章を作るため、自然さと正しさは一致しないからです。

  2. TransformerのAttentionは何をしていると説明できますか。
    回答例

    文章内の各トークンが、ほかのどのトークンをどの程度参照するかという関連の強さを計算します。

  3. GPUがAIで使われる主な理由は何ですか。
    回答例

    深層学習で必要な同種の計算を、大量に並列実行して高い処理量を出しやすいからです。
